2.2.7
- Fixed NameError crash in yt-dlp executable error handler where 'e' was referenced instead of 'exc', silently swallowing the original exception and producing incorrect error classification
- Fixed socket resource leak in has_internet_connection where the TCP socket was never closed after a successful connection check
- Fixed pycurl handle leak in Worker: curl handles were created at construction but never explicitly closed, accumulating across many downloads
- Fixed pycurl handle leak in Worker_Sparse: same pattern as Worker, now cleaned up via __del__
- Fixed Youtube stream download expiry on resume via cURL as download engine
- Fixed unused imports in worker_sparse (Lock, size_format) carried over from an earlier refactor
- Fixed yt-dlp Done vs Size column mismatch in the download table: yt-dlp fires its progress hook separately for each DASH stream (video then audio), resetting downloaded_bytes to 0 for each new stream; the hook now banks bytes from each finished stream and accumulates a cumulative total seeded from d.size + d.audio_size so Done and Size stay consistent throughout the entire download, not just at completion
- Fixed File Properties dialog always displaying 0% progress: was reading the raw d._progress field (0 at init, not persisted across restarts) instead of the d.progress property which correctly returns 100 for completed items and computes from downloaded/size for active ones
- Fixed AdvancedMetadataDialog and folder picker appearing behind the Add Download window: both were parented to the main QMainWindow so the window manager placed them behind the already-visible AddDownloadWindow; now parented to ui_add_download directly
- Fixed Retry button not refreshing the thumbnail when the same YouTube URL is reprocessed: show_thumbnail() skipped the network fetch because the URL string was identical to the cached current_thumbnail; reset current_thumbnail to None on retry
- Improved resolution combo box ordering: streams are now sorted ascending within each group and arranged audio (♫) first, then other video formats (◆), then MP4 (▶), making quality tiers easier to compare and differentiate at a glance
- Improved _thread_manager_sparse: replaced 20 Hz busy-poll (sleep(0.05) + t.is_alive() scan) with a queue.Queue completion notification, eliminating ~20 wasted CPU wake-ups per second per active sparse download
- Improved _file_manager_sparse: reduced polling interval from 0.05s to 0.1s, halving CPU overhead during file completion monitoring
- Improved run_ytdlp_download (Python API): added 0.18s throttle to progress hook UI signal emissions, preventing Qt main thread saturation on fast connections where yt-dlp fires the hook dozens of times per second
- Fixed PopulateTableWorker never emitting its finished signal after run() completed; the thread's quit() slot was connected to this signal and therefore never called, leaving the thread's event loop running indefinitely — subsequent populate_table() calls always found t.isRunning() == True and skipped, so new downloads never appeared in the table until app restart. (#100)
- Performance: eliminated UI-blocking t.wait(2000) in populate_table; if the previous worker thread is still running the current cycle is skipped rather than stalling the main thread for up to 2 s; guard added for PySide6 RuntimeError when isRunning() is called on a QThread whose C++ object was already destroyed by deleteLater. (#101)
- Performance: save_d_list and save_settings are now debounced to ~5 s intervals (20 × 250 ms ticks) instead of running on every GUI tick; on-demand saves for user actions (delete, start, stop, add) are unaffected. (#101)
- Performance: populate_table_apply no longer calls save_d_list, eliminating a duplicate SQLite write that occurred in addition to the tick-based save. (#101)
- Performance: replaced O(n) find_download_by_id linear scan in update_table_progress with an O(1) _d_index dict built during populate_table_apply; eliminates O(n²) comparisons per tick for large download lists. (#101)
- Performance: update_table_progress now refreshes speed, ETA, done, size, and status columns for all active downloads in the same pass. (#101)
- Performance: added finalization pass in update_table_progress — downloads that just left active_ids receive one final column flush (terminal status, final size) before being marked finalized. (#101)
- Fixed shutdown cascade failure: RuntimeError from calling isRunning() on a deleteLater-destroyed QThread C++ object inside closeEvent was short-circuiting the entire shutdown try-block, leaving LogRecorderThread and BrowserQueueMonitor running and producing QThread: Destroyed while thread is still running warnings. (#102)
- Performance: replaced module-level Lock() shared across all DownloadItems with a per-instance self._lock; previously all concurrent downloads contended on a single global lock in the downloaded setter (called thousands of times per second from 64 worker threads per download). (#101)
- Performance: moved _RE_BYTES_NUM regex from per-instance compilation in __init__ to a module-level constant; eliminates N redundant compiled regex objects for N downloads loaded from history. (#101)
- Performance: removed unnecessary lock acquisition from the speed property inactive-status early-return path; this path fires for every non-downloading row on every update_table_progress tick and only writes a single float which is GIL-atomic. (#101)
- Performance: replaced per-download monitor threads in run_curl_download with a single shared daemon thread (_SharedCurlMonitor); previously each concurrent cURL download spawned its own Thread sleeping 0.5 s in a loop — 10 concurrent downloads meant 10 sleeping threads each holding an OS stack and contributing to GIL pressure; the shared monitor handles all downloads in one 0.5 s tick regardless of concurrency. (#102)
- Fixed latent bug in Segment.split() where start, end = self.range failed for the string ranges produced by idm_style_splitter (e.g. "0-1234567"); split now parses string ranges before unpacking. (#104)
- Implemented IDM-style dynamic segment splitting: _thread_manager_sparse now pre-creates the full max_connections worker pool upfront (matching idm_style_splitter's design intent) and calls native_engine.find_struggler() every 2 s to detect stalled connections; when a connection is 3× slower than the average and has >10 MB remaining, its undone half is split off and handed to an idle worker — connections scale dynamically from the initial 2–4 up to the configured maximum during the download. (#104)
- Added clean abort path for dynamically split segments: when find_struggler shrinks a running worker's segment_size, write() sets _segment_done=True which causes the pycurl progress callback to return -1 (CURLE_ABORTED_BY_CALLBACK); run() treats error 42 as a clean segment completion rather than a network error, stopping the connection immediately instead of draining wasted bandwidth to the original range end. (#104)
- Added IDM-style per-connection segment map to the download window details area: a custom SegmentMapWidget draws each active connection as a coloured block positioned at its byte-range start, growing rightward as bytes are written — idle slots are hidden from the connections table and the map shows allocated-but-pending regions in a muted tone so progress is visible at a glance. (#105)
- Fixed critical bug in Segment.split() where the child segment inherited the parent's filename: replace(f'{num}.', ...) only matched when a dot followed the number, so names like '0_audio' produced no substitution and multiple workers silently wrote to the same output file, corrupting it. Now strips the leading digit prefix from the basename and prepends the new segment number instead. (#106)
- Fixed Worker.run() crashing with 'tuple' object has no attribute 'split' when a dynamically split segment carries a tuple range: range parsing is now done once at the top of run() with an isinstance guard before the resume logic, and set_options() converts any tuple range to the 'start-end' string pycurl expects. (#106)
- Fixed Worker retry loop treating pycurl error 23 (CURLE_WRITE_ERROR) as a network fault: write() intentionally returns -1 when a segment reaches its size limit, which curl surfaces as error 23; the loop now breaks immediately on error 23 rather than sleeping and retrying up to 5 times in append mode, which was growing segment files to multiples of their expected size and causing verify() to fail. (#106)
- Fixed per-connection segment map not populating during DASH/YouTube downloads: thread_manager now pre-initialises connection_stats with start_byte and segment_size slots (mirroring _prep_and_download), and Worker.run() publishes its parsed byte-range to connection_stats before the first byte is written. (#106)
- Fixed corrupted video/audio after dynamic splitting: file_manager was stitching segments in list-insertion order (seg.num order), but dynamic splits assign higher nums to chunks that cover earlier byte positions; added _seg_byte_order_key and sort segments by (tempfile, range_start_byte) before stitching so each stream is always reassembled in the correct byte sequence. (#107)
- Fixed segment map bar leaving a gap on the right during YouTube/DASH downloads: audio segments have byte positions relative to their own stream (starting at 0), but the bar's total is video_size + audio_size; Worker.run() now adds d.size (video stream size) as an offset to the audio segment's start_byte so the audio blocks appear in the right-hand portion of the bar rather than overlapping the video blocks at the left. (#108)
- Fixed total_size property double-counting audio size for yt-dlp DASH downloads: the yt-dlp progress hook updates d.size to the combined (video + audio) total; total_size previously added d.audio_size on top of that; now returns d.size directly when engine == 'yt-dlp'. (#108)
- Added segment map support for yt-dlp downloads: progress hook now publishes start_byte (stream offset in the combined bar) and segment_size (current stream size) to connection_stats[0] so the SegmentMapWidget can draw a live progress bar; during video download the bar fills left-to-right across 0-86%; during audio it fills the remaining 86-100%. (#108)
- Fixed segment map gap at the right end of the bar for HLS/m3u8_native downloads: the total_size property's fragment-size estimator (avg_seg_size × n_segs) computed a larger total than the fixed 200 KB virtual slots used by Worker.run(), so slot positions shifted left and left a proportional gap empty at the right; _update_info() now always overrides _total with n_segs × 200 KB for m3u8_native regardless of whether total_size has been estimated, ensuring the widget scale exactly matches the worker's virtual positioning. (#109)
- Added HLS/m3u8_native URL refresh on expiry: when pre_process_hls() fails (CDN token expired), run_curl_download() now calls _refresh_hls_urls() which re-runs yt-dlp on the original platform URL, matches the format by format_id (falling back to height), and updates d.manifest_url / d.eff_url / d.audio_url before retrying pre_process_hls(); Worker.run()'s existing-file check ensures already-completed .ts segments are not re-downloaded. (#109)
- Fixed segment map colored fills not reaching their slot boundaries: Worker.write() was pushing a per-call delta (+= written) to connection_stats["downloaded"] inside a 0.1 s throttle gate, so only the bytes from the single write call that happened to fall on a gate boundary were counted — all other bytes were silently dropped; changed to push the absolute running total (= self.downloaded) so every throttle tick captures all bytes written since the segment started. (#108)
- Fixed completed segments not showing 100% fill in the segment map: report_completed() in both Worker and Worker_Sparse now sets downloaded = segment_size for the slot so the block always appears fully filled once the segment finishes, regardless of whether the actual byte count matches the virtual slot size (relevant for HLS). (#108)
- Fixed segment map showing nothing during HLS/m3u8_native downloads: HLS segments have no byte range (range=None), so start_byte and segment_size were both 0 and the widget skipped every slot; Worker.run() now assigns each HLS segment a 200 KB virtual slot (start_byte = seg.num × 200 KB, segment_size = 200 KB) so all 30+ connections appear as evenly-tiled blocks on the bar; SegmentMapWidget.paintEvent() clamps downloaded to segment_size to prevent virtual slots from overflowing into neighbouring blocks, and _update_info() derives the matching virtual total (n_segs × 200 KB) when d.total_size is 0. (#108)
- Fixed aria2c downloads ignoring the proxy setting: run_aria2c_download and run_aria2c_video_audio_download now forward config.proxy (with credentials if set) as the aria2c per-task all-proxy option so HTTP/SOCKS proxies apply to aria2c the same way they do for cURL and yt-dlp. (#108)
- Fixed Segment.split() placing the split point at the absolute midpoint of the declared range rather than the midpoint of the remaining (unwritten) bytes: when a segment is actively downloading, the worker may have already written past the absolute midpoint by the time the split is applied, so the new self.size falls below the current file size, the write() size-guard fires immediately, and verify() fails with an oversized part-file; now the split point is computed as current_head + remaining//2 (where current_head = range_start + os.path.getsize(part_file)), which always places the boundary ahead of what has been written, allowing the running worker to stop cleanly at the correct size with no overlap or verify failure. (#108)
